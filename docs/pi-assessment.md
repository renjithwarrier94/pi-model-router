# Pi assessment and routing (explicit opt-in)

Load `src/index.ts` from the repository root with `pi --extension ./src/index.ts`. **Automatic routing is off by default.** The adapter prefers Pi's OpenRouter credentials (`/login openrouter`), then `OPENROUTER_API_KEY`, then `TYPESAFE_API_KEY`. OpenRouter sends to Jev 1.13 at `https://openrouter.ai/api/v1/systemone`; direct TypeSafe uses `jev-latest`. Jev is separate from Pi's coding model. No key is stored in router config and the recipient never changes silently after consent.

## Commands

- `/model-router-assess once`: send the next prompt's prepared context to Jev and display five judgments; never switch models.
- `/model-router-route once`: assess and potentially switch the Pi model/thinking level for the next prompt. The model remains active afterward; *permission to reassess* is one-shot.
- `/model-router-auto on`: in a **trusted project with an interactive TUI or RPC client**, check credentials and routing config, then ask for an explicit confirmation describing future unredacted transmissions and the named recipient. Only if confirmed, route **each subsequent prompt in this session** without asking again. RPC clients must answer the Pi `confirm` request; it times out after 30 seconds. Print/JSON modes cannot enable automatic routing.
- `/model-router-auto off`: revoke automatic and any pending one-shot permission. `/model-router-assess off` and `/model-router-route off` do the same. Enabling either one-shot command *replaces* automatic consent rather than pausing it; enabling automatic routing replaces one-shot consent. Invalid commands do not grant permission.

Automatic consent is **in memory only**: it is not a config flag or a session entry. It is cleared on session start/shutdown, tree navigation, extension reload, explicit revocation, lost trust, changed recipient, or an unexpected routing failure. The compact `Router auto: <recipient>` status remains visible while it is enabled, separately from the assessment status. A subsequent prompt re-resolves credentials before reading context; if the recipient has changed, routing stops and consent must be renewed. Explicit `off` aborts an in-flight Jev assessment when possible and ignores late results; a request already transmitted cannot be unsent, and a Pi model switch already started may complete. Inspect Pi's active model if revoking mid-switch.

The `before_agent_start` pipeline is `mapContext()` → `prepareContext()` → `assessTask()` → `selectModel()` → `setModel()`/`setThinkingLevel()` (routing also loads configuration and checks runtime candidates **before** sending to Jev). One-shot permission is consumed before prompt-bearing work; auto permission remains only while its session-scoped conditions hold. Stale results after session/branch changes, revocation, newer requests, or an aborted turn cannot switch models. No router results or raw input are injected into the model transcript or stored as extension entries; Pi records its own model-change entry when switching.

Successful assessments appear only in Pi's status area (TUI/RPC), not in the model transcript: `Router: <category> R<score> S<score> I<score> M<percent>% W<score>`. R = reasoning, S = dependency scope, I = context integration (0–2); M = probability of missing critical evidence; W = normalized policy-weighted demand (0–1). Assessment-only shows `W–` without a readable policy. The line clears on a new operation and session/tree changes; it never includes the chosen model. Errors, skipped routes, and threshold-unmet fallbacks appear as sanitized notifications. One-shot commands may be invoked in non-UI modes, but cannot show a status line there.

## Safety and limits

**Privacy:** consent is **not redaction**. Current prompts and selected historical user/assistant text can contain secrets and are sent unredacted through the confirmed recipient (and potentially onward to TypeSafe as the model provider); image counts and omission notices may be sent, but not image bytes, tool calls/results, system prompts, extension messages, or assistant thinking. Auto mode deliberately grants broader consent for *future* prompts that cannot be reviewed in advance. Do not enable it for sessions where future text might be sensitive. It makes no claim to detect secrets. Jev instructions distinguish conversation evidence from instructions, but prompt-injection resistance is not guaranteed.

Routing requires both `policy` and nonempty `options` in the global `~/.pi/agent/model-router.json` (or `PI_CODING_AGENT_DIR`) and/or trusted project `.pi/model-router.json`; see [configuration](configuration.md). Invalid/unreadable config, no eligible models, unknown context usage, an oversized request, assessment failure, an `unclear` category, or high missing-evidence probability leave the current model unchanged. A threshold-unmet fallback selects the highest-scoring compatible option with a warning. Config/credential failures in auto mode revoke consent; ordinary per-prompt skips do not. If an error occurs after switching, inspect Pi's active model.

**Quality:** weights, DeepSWE mappings, and costs remain uncalibrated; DeepSWE primarily measures coding, not explanation/design/research. The context capacity estimate is conservative, not a provider guarantee. The [offline evals](../evals/README.md) are synthetic regression tests, not real-world validation. Keep auto off in workflows where inaccurate routing would be consequential until empirical calibration and privacy controls are stronger.
